# 隐言加密输入法 - 功能需求规格说明书

> 版本: 2.0 | 日期: 2026-05-17
> 状态: 需求定义（脱离语燕框架，面向通用输入法实现）

---

## 1. 项目概述

### 1.1 产品定位

隐言是一款具备端到端加密通信能力的输入法应用。用户在任意聊天场景中，通过输入法内置的加密功能，将明文实时转换为伪装密文上屏，接收方通过同一输入法自动解密还原。密文在传输过程中伪装为普通社交内容，实现隐蔽通信。

### 1.2 核心价值

| 维度 | 描述 |
|------|------|
| 安全性 | 国密算法（SM9/SM4）端到端加密，私钥不出设备 |
| 隐蔽性 | 密文伪装为普通社交内容，不引人注意 |
| 无感化 | 加解密在输入法内完成，无需切换应用 |
| 跨平台 | Android 与 Windows 端密钥同步、密文互通 |

### 1.3 目标用户

需要在即时通讯工具中进行私密通信的用户，对通信内容有保密需求。

## 2. 加密模式

### 2.1 模式总览

| 模式 | 算法 | 密钥类型 | 输出形态 | 适用场景 |
|------|------|----------|----------|----------|
| SM9 标识加密 | SM9-IBE | 非对称（KGC 颁发） | Base58 文本 | 一对一/一对多加密通信 |
| SM4 对称加密 | SM4-CBC | 对称（共享密钥） | Base58 文本 | 群组共享密钥通信 |
| 密码本 | 坐标位移 | 对称（4 位数字索引号） | 汉字等长替换 | 离线/低安全场景 |
| Emoji | 矩阵映射 | 对称（4 位数字索引号） | Emoji 序列 | 视觉伪装场景 |

### 2.2 SM9 标识加密模式

**加密流程**:
```
明文 → UTF-8 字节 → SM9 加密(目标用户 ID) → Base58 编码 → 协议头拼接 → 模板包装 → 上屏
```

**解密流程**:
```
剪贴板密文 → 协议头识别 → 模板剥离 → Base58 解码 → SM9 解密(我的 ID) → UTF-8 → 明文
```

**密钥管理**:
- 主公钥 (MPK): 从 KGC 服务端获取，全局共享
- 用户私钥: 从 KGC 服务端获取，绑定用户 ID，密码保护存储
- 加密时仅需目标用户 ID，无需对方公钥

**协议标识头**: `⸝ ` (U+2E1D + 空格)

### 2.3 SM4 对称加密模式

**加密流程**:
```
明文 → UTF-8 字节 → SM4-CBC 加密(KEY, IV) → Base58 编码 → 协议头拼接 → 模板包装 → 上屏
```

**解密流程**:
```
剪贴板密文 → 协议头识别 → 模板剥离 → Base58 解码 → SM4-CBC 解密(KEY, IV) → UTF-8 → 明文
```

**参数规范**:
- 模式: SM4/CBC/PKCS7Padding
- 密钥: 16 字节（128 bit）
- IV: 16 字节，与密钥配对管理
- 编码: Base58（Bitcoin 标准，字母表 `123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz`）

**协议标识头**: `⸝ ` (U+2E1D + 空格) — 与 SM9 共享标识头，通过密文长度/格式区分

### 2.4 密码本模式

**加密流程**:
```
明文 → 逐字查坐标 → 坐标位移(KI, KP) → 映射目标汉字 → 协议头拼接 → 上屏
```

**双轨加密**:
- 汉字: 坐标位移，公式 `p' = (p + KP) mod 149, i' = (i + KI) mod 100`
- 数字/字母: 62 字符混淆，公式 `C' = Charset[(Index + KS) mod 62]`，其中 `KS = KP + KI`
- 符号: 不参与加密，原样输出

**密钥**: 4 位数字索引号，前两位为 KP，后两位为 KI

**输出特征**: 1:1 等长替换，密文与明文等长

**协议标识头**: `⸝` (U+2E1D，无空格)

### 2.5 Emoji 模式

**加密流程**:
```
明文 → UTF-8 字节 → (high, low) 拆分 → 62×16 矩阵坐标变换 → Emoji 映射 → 协议头拼接 → 上屏
```

**算法细节**:
- 每字节拆分: `high = byte / 62`, `low = byte % 62`
- 坐标变换: `row = (index + KI) % 62`, `col = KP % 16`
- 矩阵: 62 行 × 16 列 = 992 个安全 Emoji 码点（排除 ZWJ、肤色修饰符）

**密钥**: 4 位数字索引号，与密码本共享格式

**协议标识头**: `⸝·` (U+2E1D + 中点)

## 3. 协议规范

### 3.1 隐言 2.0 标识头

| 模式 | 标识头 | Unicode | 示例 |
|------|--------|---------|------|
| 密码本 | `⸝` | U+2E1D | `⸝你好世界` |
| SM9/SM4 | `⸝ ` | U+2E1D + U+0020 | `⸝ 5HxK9m...` |
| Emoji | `⸝·` | U+2E1D + U+00B7 | `⸝·😀🎉🔥` |

### 3.2 模式检测规则

```
if (内容以 "⸝·" 开头) → Emoji 模式
else if (内容以 "⸝ " 开头) → SM9/SM4 模式
else if (内容以 "⸝" 开头) → 密码本模式
else → 非加密内容
```

### 3.3 兼容标识头（旧版，@Deprecated）

| 模式 | 旧标识头 | 微信抗过滤版本 |
|------|----------|----------------|
| 密码本 | `‌​` | `·‌​` |
| 默认 | `​‌` | `·​‌` |

> 旧版标识头仅做兼容识别，新产生的密文一律使用 2.0 标识头。

### 3.4 微信抗过滤

微信会过滤零宽字符。解决方案:
- 在标识头前添加 `·` (中点) 作为可见前缀
- 2.0 版本使用 `⸝` (U+2E1D RAISED COMMA) 替代零宽字符，天然抗过滤

## 4. 伪装模板系统

### 4.1 功能描述

加密后的密文通过伪装模板包装，使其看起来像普通社交内容。

### 4.2 模板格式

模板包含 `%s` 占位符，加密后将密文嵌入:

```
模板前缀 %s 模板后缀
```

示例:
```
砍刀模板: "砍价群发！%s 快来抢！"
抽奖模板: "恭喜中奖！%s 点击领取！"
```

### 4.3 预置模板

| 序号 | 类型 | 说明 |
|------|------|------|
| 1 | 砍刀 | 伪装为砍价消息 |
| 2 | 抽奖 | 伪装为中奖通知 |
| 3 | 领券 | 伪装为优惠券消息 |
| 4 | 游戏 | 伪装为游戏邀请 |
| 5 | 红包 | 伪装为红包消息 |
| 6 | 链接 | 伪装为分享链接 |

### 4.4 模板管理

- 支持增删改查
- 支持搜索过滤
- 支持分页加载
- 模板选择状态持久化

### 4.5 模板与解密

解密时需从模板包装中提取密文:
- 使用 `indexOf(标识头)` 定位密文起始位置
- 从标识头开始提取密文部分
- 去除模板前后缀后执行解密

### 6.1 功能描述

索引号是密码本模式和 Emoji 模式的共享密钥，格式为 4 位数字。

### 6.2 数据模型

## 7. 解密功能

### 7.1 剪贴板自动解密

**触发条件**: 当系统剪贴板内容变化时，自动检测并解密。

**流程**:
```
剪贴板变化 → 检测标识头 → 识别模式 → 剥离模板 → 解密 → 显示结果
```

### 7.2 抢跑嗅探

**触发条件**: 输入法窗口显示时（`onWindowShown`），主动抓取剪贴板内容。

**目的**: 在用户手动粘贴之前，提前完成解密准备。

### 7.3 Hash 指纹校验

**问题**: 防止已处理的密文被重复解密（"回魂"问题）。

**机制**:
- 处理密文时记录其 Hash 指纹
- 再次遇到相同 Hash 的内容时跳过
- 用户手动复制新内容时重置指纹

**指纹记录时机**: 点击关闭按钮 / 提交解密结果
**指纹重置时机**: 剪贴板 `onPrimaryClipChanged` 触发

### 7.4 全模式分发

解密时根据标识头自动识别模式并分发到对应解密算法:

```
检测到 ⸝· → Emoji 解密
检测到 ⸝  → SM9/SM4 解密
检测到 ⸝  → 密码本解密
无标识头   → 跳过
```

## 10. 密钥管理

### 10.1 SM9 密钥

| 密钥 | 来源 | 存储 | 保护 |
|------|------|------|------|
| 主公钥 (MPK) | KGC 服务端 | 本地文件 | 无需保护 |
| 用户私钥 | KGC 服务端 | 本地文件 | 密码加密 |

**API 设计**:
```
initMasterPublicKey(mpkFilePath)     // 初始化主公钥
initMyPrivateKey(myId, keyFilePath, password)  // 初始化私钥
encrypt(plaintext, targetId)         // 加密（需目标用户 ID）
decrypt(ciphertext, myId)            // 解密（需我的 ID）
```

### 10.2 SM4 密钥

| 密钥 | 来源 | 存储 | 保护 |
|------|------|------|------|
| 对称密钥 | 预共享/KGC 分发 | 本地 | 待定 |
| IV | 与密钥配对 | 本地 | 待定 |

### 10.3 密码本/Emoji 索引号

| 密钥 | 来源 | 存储 | 保护 |
|------|------|------|------|
| 4 位数字索引号 | 用户自定义/共享 | Room 数据库 | 无额外保护 |

### 10.4 安全约束

- 私钥不出设备
- 密文不留本地痕迹（解密结果关闭后清除）
- 密钥文件安全存储（待实现）

## 附录 A: Base58 编码规范

**字母表**: `123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz`

**编码规则**:
- 统计前导 `0x00` 字节数
- 字节数组转 `BigInteger`
- BigInteger 转 Base58 字符串
- 前导 `0x00` → 前导 `'1'` 字符

**解码规则**:
- 统计前导 `'1'` 字符数
- Base58 字符串转 `BigInteger`
- BigInteger 转字节数组
- 移除可能的 `0x00` 符号位前缀
- 前导 `'1'` → 前导 `0x00` 字节

## 附录 B: GmSSL 集成规范

**版本**: v3.1.1（主分支有 kyber.h 编译 bug）

**编译配置**:
```bash
NDK_PATH="<Android NDK 路径>"
cmake .. -G "Unix Makefiles" \
  -DCMAKE_TOOLCHAIN_FILE="$NDK_PATH/build/cmake/android.toolchain.cmake" \
  -DANDROID_ABI=arm64-v8a \
  -DANDROID_PLATFORM=android-23 \
  -DBUILD_SHARED_LIBS=ON
```

**库加载顺序**（重要）:
```kotlin
System.loadLibrary("gmssl")      // 先加载核心库
System.loadLibrary("gmssljni")   // 再加载 JNI 库
```
